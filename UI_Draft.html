1
Order bar. Free text, so the commander never learns a command syntax. The LLM does the parsing.
2
Fleet strip. Battery, capacity and drain are the numbers the verifier reasons about, so they stay on screen — a refusal should be readable off the cards.
3
Verdict. The one panel I care most about: an UNSAT has to name the rule that failed, or the audience just sees “computer says no”.
4
Map. Rock, tunnel, flooded cells and the methane pocket, with the A* route drawn on top. Already renders from the real planner.
5
Belief heatmap. Next piece of work. Needs the HMM filter’s predict/update finished before there is anything to draw.
6
Conflict panel. Only meaningful once two robots move at once, so it is the last thing I’ll add.
7
Reasoning log. Thought / action / observation per step, tagged by which gate passed or blocked it. This is the evidence that nothing is trusted on the LLM’s word.
8
Database tabs. Proof that the state is real and persistent, not held in the prompt.
Open questions I’d like feedback on
  • Should the belief heatmap overlay the map, or sit beside it? Overlaying is prettier; side by side makes the drift easier to compare against the truth.
  • Is one screen enough, or should the reasoning log get its own tab so the map can be bigger during a live demo?
  • For an UNSAT, is the solver’s own diagnostic JSON worth showing on screen, or should it be a plain sentence with the JSON tucked behind a toggle?
